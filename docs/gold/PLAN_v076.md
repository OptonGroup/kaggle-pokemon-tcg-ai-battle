## Фаза 1 — диагностика fidelity против ПРАВИЛЬНОГО эталона

Прибор готов: `scripts/fidelity_expert_topk.py` (offline top-1 agreement полного пилота
против реальных решений эксперта на его же fog-of-war наблюдении; детерминированно, без
live и без гейта — шумовые полы ±50 μ и ±1-2 пп здесь не действуют).

```bash
.venv/bin/python scripts/fidelity_expert_topk.py \
    --candidate v075_promo \
    --daily-root out/top5_recon --days 2026-07-23 \
    --targets Luca "Dominic Peel" "szlachetny snieg" \
    --out out/v076_fidelity/topk_top3.json \
    --rows-out out/v076_fidelity/rows_top3.jsonl
```

Две адаптации, которые почти наверняка потребуются (заложить время):
* прибор ждёт `<daily-root>/<day>/*.json` — структура `out/top5_recon/2026-07-23/episodes/`
  отличается одним уровнем; либо симлинк, либо флаг;
* определение «кто эксперт в этой игре» прибор берёт из имён команд в дампе. В скачанных
  через API реплеях их может не быть — **готовый обходной путь**: `team` и `side` уже лежат
  в `out/top5_recon/2026-07-23/index.csv`, передать их прибору как явный маппинг
  `episode → (team, side)`.

**Новое требование к разрезу.** v074 считал agreement только по категориям решений. Теперь
нужен двойной разрез: **категория решения × матчап оппонента** (архетип берётся из
`out/top_players_ledger.csv`, колонка `opp_arche` / `opp_has_crustle`). Приоритет —
ячейки с максимумом (разрыв WR в матчапе) × (частота категории).

**Критерий выхода Фазы 1:** список ячеек, где agreement < 50% и частота > 2% решений,
отсортированный по вкладу. Отдельно — таблица по Crustle-стене (68 игр эталона против
наших 43): там разрыв 23 пп, и он должен где-то проявиться в решениях.

**Ловушка (вечнозелёная):** off-by-one `obs[i] ↔ action[i+1]` —
см. `project_offbyone_forensic_bug`. `src/replays/parse.py::parse_replay()` уже это
учитывает; не переписывать пайплайн заново.

## Фаза 2 — развилка, выбирать ПО данным Фазы 1

### 2A — расхождения локализованы (≤5 категорий дают >60% разрыва)

Пакет правил эвристики. **Жёсткое условие: не сабмитить по одной.** Копить, пока
суммарный ожидаемый эффект на гейте не даст ≥5 пп по полю. Каждая правка проверяется
offline-verify (сколько решений изменилось, сколько из них в сторону эталона) до гейта.

### 2B — расхождения размазаны (нет доминирующих категорий)

Замена политики: BC/IL-клон на корпусе Фазы 0.
* **Почему это не повтор v070.** v070 был BC-клоном внешнего пилота prvsiyan, чей
  собственный live ≈737 — клон унаследовал потолок автора (см.
  `lessons_grimmsnarl_shipped_chain_v044_v073`). Здесь автор делает 63%, потолок другой.
* Форма — гибрид: BC как приоритизатор ходов, наши проверенные guard'ы (promotion, KO,
  energy) как safety-слой и fallback. Полная замена пилота на сеть — не делать.
* Ограничение из `project_bc_combo_failure`: BC работает на midrange aggro — Grimmsnarl
  подходит.

## Фаза 3 — измерение (единственный допустимый способ)

1. **Offline:** top-1 agreement против эталона до/после. Это основной прибор — десятки
   тысяч решений, шумовой пол пренебрежим.
2. **Гейт:** h2h против v075 + внешние агенты пула. Требование из `MEASUREMENT_POLICY.md`:
   **≥+5 пп по полю, реплицировано на ≥2 сидах, p<0.01**, 0 регрессий, 0 исключений.
3. **Отдельная страта — Crustle-стена.** Сейчас live 30%, эталон 53%. Целевой показатель
   на гейте ≥45%. Это единственный матчап, где есть и эталонная цифра, и внешний агент.
4. Стратифицированное измерение обязательно (по-парно + обратно-дисперсионные веса +
   контрольная страта) — `project_gate_stratified_measurement`, пулинг сырых счётчиков
   даёт парадокс Симпсона.

## Риски

* **Survivorship в эталоне.** Топ-команды отобраны *по* высокому WR, часть превосходства —
  удача. 835 игр и одинаковое направление во всех матчапах говорят, что эффект реален, но
  истинный разрыв, вероятно, ближе к 6 пп, чем к 8.
* **Объём корпуса** может не дотянуть до BC (см. критерий Фазы 0).
* **Kaggle 429** при массовой докачке — `download_episodes.py` уже держит ≤2 потока с
  бэкоффом, не увеличивать concurrency (`project_kaggle_kgat_token`).
* **Дедлайн 2026-08-16** — примерно 3 недели. Фаза 1 обязана уложиться в 1–2 дня, иначе
  на Фазу 2B времени не останется.
