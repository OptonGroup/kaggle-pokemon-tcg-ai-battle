## 2. Диагноз: почему 47%, а не 60%

1. **Поиск пасует 48% ходов** — END получает высшую оценку value-модели (461 случай,
   все `src=search`). Прямые гварды опровергнуты гейтом. **Разведка 08-08 дала
   механизм**, который раньше не был найден (B1):
   - *horizon effect / асимметрия глубины*: ветви достигают depth=3 через разное
     число handover'ов → статическая оценка сравнивает несопоставимые позиции,
     «дешёвые по глубине» пассивные ветви систематически выглядят лучше (документир.
     failure mode KataGo «пасует, когда считает себя впереди»);
   - *state-value вместо action-advantage*: GBM оценивает состояние после хода, а не
     преимущество хода — END vs слабая атака неразличимы в шуме;
   - *та же болезнь решена DeNA в Pokemon TCG Pocket* (CEDEC-2026): таргет оценки
     промежуточных под-действий = изменение оценки ПОСЛЕ ПОЛНОГО хода, не
     промежуточного состояния.
2. **Бюджет времени не потрачен**: медиана 18.4с из 600с (3%). Рычаг samples
   исчерпан (32→64 = +0.3пп), но качественные рычаги (структура оценки, root-parallel
   голосование детерминизаций) не тронуты.
3. **Гейт-пул не похож на поле, на котором нас бьют**: в CORE-пуле нет ни одного
   реального Grimmsnarl-агента уровня 800+ и нет archaludon уровня поля. Теперь ЕСТЬ
   из чего собрать: скачан рабочий код jazivxt-Alakazam (**994.2**), prvsiyan-router
   Tusk/Crustle (**844.4**), tetsutani-Grimmsnarl (**800.8**, полный каскад с BC-анс.),
   SOUTA Tusk/Crustle mill (оригинал), SOUTA-Lopunny реконструкция.
4. **Слот-рулетка**: идентичные копии расходятся на 30–400μ (подтверждено и извне,
   тред 733083). Но после дедлайна частота эпизодов вырастет и финальные 2 сабмита
   доиграются ближе к истинной силе → **инвестировать в силу агента, а не в лотерею
   сабмит-слотов**.

## 3. Рычаги, ранжированные по EV (что делаем)

### R1. Структурный фикс оценки листа поиска (дни 1-3, самый высокий EV)
Механизм пассивности найден (§2.1) — чинить причину, не симптом:
- **(a) Оценивать листья на границе хода**, не на промежуточном состоянии: развернуть
  ветвь до конца нашего хода (или до handover), и только там звать value-модель.
- **(b) Нормализация по глубине/handover**: сравнивать только листья с одинаковым
  числом handover'ов; либо штраф/дисконт за «дешёвую глубину».
- **(c) Advantage-ранжирование**: переобучить GBM с pairwise (Bradley–Terry) лоссом
  «опция A лучше опции B на одном состоянии» вместо pointwise state-value.
  Переобучение — минуты (2.1М решений в `~/poke/scout/out/decisions/`, sklearn).
- **(d) UCB-шкала**: z-нормализовать value перед exploration-термом, перебрать C.
Гейт-критерий: END-при-доступной-атаке < 20% ходов (сейчас 48%) И дельта по
перевзвешенному полю ≥ +3пп, знак на 2 реранах, p<0.01. Правки (a)-(d) мерить ПО ОДНОЙ.

**Пометка 08-09 про (c) — заявленный вид невыполним, проверено по факту схемы
данных.** `~/poke/scout/out/decisions/*.parquet` (проверено на
`2026-07-22_027.parquet`, 20078 строк × 40 колонок: `n_options`, `action0` — только
ИНДЕКС выбранного действия, `reward` — итог всего эпизода, транслированный на
каждую строку решения) и `~/poke/scout/out/corpus/*.parquet` (та же партия, 10
колонок: `options` — список опций как они были в `obs.select`, `action` — выбранный
индекс, `reward` — тот же broadcast episode-level итог) содержат **только выбранное
действие + бродкаст-исход эпизода**. Оценок невыбранных сиблингов (опций, которые
агент НЕ выбрал в этом узле) нет ни в одном из двух каталогов — Bradley–Terry
"A лучше B на одном состоянии" требует пары (A,B) с относительным лейблом, которых
здесь физически нет. Действующая value-модель (`~/poke/scout/out/value_model.json`,
проверено: `type=gbm`, `n trees=200`, `n features=45`) обучена не на "2.1М решений",
а на `~/poke/scout/out/value_states.parquet` — **252 250 строк** (проверено:
`df.shape[0]`), pointwise state-value, как и описано в §2.1 выше. Замена варианту
(c) в его заявленном виде:
  - **(c′) advantage-нормировка на инференсе** — не переобучение, а пересчёт: для
    каждого узла вычитать из value каждой опции baseline узла (среднее/медиану value
    по всем опциям этого узла), ранжировать по разнице; работает на существующей
    pointwise-модели без нового датасета;
  - **(c″) генерация pairwise-корпуса self-play'ем через cg_native** — обыграть
    N партий, на каждом реальном узле решения оценить value ВСЕХ опций (не только
    выбранной) той же pointwise-моделью или прямым rollout'ом, сохранить как новый
    датасет с парными лейблами — это и есть путь получить данные, которых сейчас
    нет, а не переобучение на существующих.

**Пометка 08-09 про гейт-критерий END-при-доступной-атаке.** Как эта метрика была
реализована 08-08 (`submissions/scout_r1a_endturn/main.py:791-795`), она считает
значение **ПОСЛЕ** `_p0_p1_guard` (`main.py:200-238`) — а этот guard сам подменяет
END на ATTACK, когда ATTACK доступна (`is_useful()`), поэтому после guard'а метрика
структурно стремится к ~0% и не воспроизводит замер "48%, 461 случай", на который
ссылается §2.1. Как критерий гейта в этом виде метрика непригодна — она измеряет
guard, а не поиск. Честный инструмент уже собран отдельно и НЕ трогает
эталоны/`scout_r1a_endturn`: `scripts/measure_search_passivity.py` — снимает RAW-
argmax (сырой `search_choice(obs)` до guard'а) и FINAL (после guard'а, если он есть)
раздельно, через monkey-patch на свежезагруженном инстансе кандидата. Правильный
прибор для гейт-критерия R1 — **RAW argmax внутри поиска**, не FINAL/post-guard.

## 6. Риски и стоп-правила
- **R1 не сдвинул END-пассивность** → не тащить гварды снова; перейти к R4 (генетика
  может выучить обход, который мы не видим руками).
- **R4 оверфитит гейт-пул** → holdout-оппоненты обязательны; кандидат, выигравший
  фитнес, но проваливший holdout, не сабмитится.
- **Просадка live при хорошем гейте** (случай scout_evo) → откат на предыдущую
  копию одиночным сабмитом (приём parallel-A/B).
- **Чужой код в гейте** — использовать ТОЛЬКО как спарринг-оппонентов; никакие куски
  чужого кода не попадают в наш сабмит (риск: наш код уже находили скопированным).
- Финал: после дедлайна эпизоды учащаются → провизионный шум финальных копий
  отыграется; решает истинный WR, не лотерея слота.
