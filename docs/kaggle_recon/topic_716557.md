## Original Post (parsed from HTML)

I'm trying to use the public episode JSON dataset for behavioral cloning / imitation learning, and I wanted to sanity-check the correct way to align observations and actions. From my parsing, each decision row has an `obs.select` with legal options and a logged action list. I'm currently filtering to rows where:

- `obs.select` is not `None`
- `maxCount > 0`
- number of legal options > 1
- selected indices are inside the option range
- `minCount <= len(action) <= maxCount`
- no final reward/rank/player identity is used as model input

A few questions:

1. Should the logged action be paired with the same step's `obs.select`, or the previous step's `obs.select`?
2. Are rows with `action=[]` but `minCount=1` expected artifacts from the logging format, or am I misaligning actions/observations?
3. Are both agents in these public episode logs generally suitable for BC, or do people filter to winner-only / specific agents / specific ranks?
4. For behavior cloning, are people mainly training on single-choice `maxCount=1` decisions first, or including multi-select decisions from the start?
5. Is there any official or commonly accepted interpretation of deck-return/start rows vs real decision rows in these logs?

Just trying to avoid training on incorrectly aligned or illegal action labels. Any clarification on the dataset format would be appreciated.
