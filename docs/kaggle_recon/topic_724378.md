## Our analysis (from engine source src/cg/api.py — SelectContext enum)
The cabt engine `SelectContext` enum has explicit ORDERING contexts:
- `SKILL_ORDER = 34` — "Skill. Select the order of effect activation."
- `FIRST_EFFECT = 44` — "YesNo. Would you like to select the first effect?"

The existence of dedicated ordering contexts implies that for MOST multi-select contexts
(multi-energy attach, multi-card discard, prize selection, etc.) the returned index list is
treated as a SET — order does not matter. Order matters only when the select context is
explicitly an "order" context (SKILL_ORDER / FIRST_EFFECT), where the returned sequence
defines the activation order.

Practical implication for our agents: when `minCount/maxCount > 1` and context is NOT
SKILL_ORDER, we can return indices in any convenient order (e.g. sorted). When context is
SKILL_ORDER, the returned order IS the activation order and must be chosen deliberately.
